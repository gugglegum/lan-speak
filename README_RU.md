# LanSpeak

LanSpeak — это одноранговый голосовой чат с ультра-низкой задержкой для Windows. В первую очередь он предназначен для игроков, которые физически находятся в одной комнате и подключены к одной проводной локальной сети. В такой ситуации голос собеседника сначала слышен напрямую через воздух, а затем повторяется в наушниках с задержкой обычной интернет-звонилки, создавая эффект «двойного голоса». LanSpeak сводит эту задержку к минимуму.

LanSpeak использует WASAPI в shared-режиме и передаёт raw PCM по UDP. Центрального сервера нет: каждый участник отправляет звук напрямую выбранным контактам.

> [!WARNING]
> Сейчас в LanSpeak нет шифрования и аутентификации участников. Используйте программу только в доверенной локальной сети.

## Возможности

- Захват и воспроизведение через WASAPI в shared-режиме: микрофон остаётся доступен игре.
- Моно PCM16 по UDP, небольшой jitter buffer и отсутствие задержки аудиокодека.
- Full-mesh-комнаты для двух и более участников без сервера.
- Общий и персональный push-to-talk, включая глобальные хоткеи.
- Индивидуальное усиление, mute и включение контакта в групповой PTT или исключение из него.
- Индивидуальный receiver-side self-ducking с настраиваемыми attack, hold и release.
- VU-метры контактов и собственного микрофона с нижней границей `-60 dBFS` и плавным затуханием.
- Игровой OSD для входящей и исходящей голосовой активности.
- Сворачивание в системный трей и защита от запуска нескольких экземпляров.
- Русский и английский интерфейс с автоматическим выбором по языку Windows.
- Отдельное консольное ядро с диагностикой устройств, захвата, воспроизведения, UDP и loopback.

## Быстрый старт

1. Поместите `LanSpeak.exe` и `LanSpeakCore.exe` в одну папку.
2. Запустите `LanSpeak.exe`. Консольное ядро автоматически запустится в фоне.
3. Если брандмауэр Windows запросит разрешение для `LanSpeakCore.exe`, разрешите доступ к **частным сетям**.
4. Выберите устройства ввода и вывода в меню **Настройки**.
5. Добавьте каждого участника в контакты, указав его IP-адрес в локальной сети и UDP-порт. Порт по умолчанию — `49740`.
6. Для формирования full mesh каждый участник должен добавить всех остальных.
7. Используйте общую кнопку разговора или назначьте общий и персональные PTT в меню **Настройки > Глобальные хоткеи**.

После запуска программа работает в режиме прослушивания, а передача микрофона выключена. Настройки и контакты сохраняются в `settings.txt` рядом с исполняемыми файлами.

## Сборка

### Требования

- Windows 10 или Windows 11, x64.
- Visual Studio 2022 с компонентом **Разработка классических приложений на C++**.
- CMake 4.2 или новее.
- Компилятор с поддержкой C++20. Поддерживаемый toolchain — MSVC.

Внешние библиотеки не требуются.

В **x64 Native Tools Command Prompt for VS 2022** выполните:

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

Готовые файлы обычно находятся в `build/Release/`:

- `LanSpeak.exe` — приложение с графическим интерфейсом, которое запускает пользователь.
- `LanSpeakCore.exe` — консольное аудио/сетевое ядро и диагностический инструмент.

MSVC-сборки используют статический runtime (`/MT` для Release и `/MTd` для Debug), поэтому готовым EXE не требуется установленный Visual C++ Redistributable.

### CLion

Откройте корень репозитория как CMake-проект и выберите toolchain **Visual Studio**. MinGW не является поддерживаемым toolchain для этой реализации под Windows/WASAPI. Основные CMake-targets: `LanSpeak`, `LanSpeakCore` и `LanSpeakTests`.

## Диагностика ядра

Ядро можно запускать непосредственно из терминала:

```powershell
LanSpeakCore.exe --help
LanSpeakCore.exe --list-devices
LanSpeakCore.exe --capture-test 10
LanSpeakCore.exe --tone-test 5
LanSpeakCore.exe --udp-audio-loopback 10 49740
```

Команда `--tone-test` воспроизводит слышимый тестовый тон. Полный список режимов и параметров выводится командой `LanSpeakCore.exe --help`.

## Архитектура

- `LanSpeak.exe` управляет контактами, настройками, хоткеями, треем, OSD и интерфейсом Windows.
- `LanSpeakCore.exe` управляет shared WASAPI-потоками, UDP-транспортом, jitter buffer, микшированием, ducking и аудиотелеметрией.
- Процессы взаимодействуют через текстовые control- и telemetry-pipes. GUI также получает диагностический вывод ядра.
- UDP-протокол v1 использует фиксированный 72-байтовый заголовок и моно PCM16. Старые и новые ядра v1 совместимы по сети.
- При частоте `48 кГц` один активный PCM-поток использует около `0,8 Мбит/с` полезной пропускной способности на каждого получателя.

Практическая цель по задержке составляет примерно `20–50 мс`, но фактический результат зависит от аудиоустройств, периодов WASAPI, драйверов, планировщика и сети.

## Структура репозитория

```text
src/common/  Общие утилиты
src/core/    WASAPI, UDP, PCM, jitter buffer, маршрутизация и диагностика
src/gui/     Win32 GUI, настройки, IPC, контакты, OSD, трей и хоткеи
tests/       Тесты CTest
assets/      Иконки приложения и превью
tools/       Скрипты для разработки
```

## Текущие ограничения

- Поддерживается только Windows; требуется WASAPI.
- Программа предназначена для доверенной LAN: аудио и служебные метаданные не шифруются и не аутентифицируются.
- Нет NAT traversal, relay-сервера, автоматического обнаружения участников и управления перегрузкой интернет-канала.
- Raw PCM уменьшает задержку и сложность ценой более высокого сетевого трафика.
- Self-ducking подавляет голос локального пользователя, который вернулся через микрофон находящегося рядом контакта; это не полноценный acoustic echo canceller.
- Проект пока экспериментальный. Перед игрой проверьте аудиоустройства и правила брандмауэра.

## Участие в разработке

Перед отправкой изменений соберите приложение и тесты, затем запустите CTest. Изменения UDP-протокола v1, CLI-команд, текстовых форматов IPC или `settings.txt` должны сохранять обратную совместимость либо включать миграцию.
